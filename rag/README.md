# 약관 RAG

LLM 설명(지표 해석, 질문 답변, 증빙 요청서, 판단 불가 보완)에 관련 표준약관 조항을 함께 넣어, 근거 조항을 인용하게 합니다.
**약관은 인용에만 쓰고 점수, 위험도, 결과 제안은 바꾸지 않습니다.**

## 파일

| 파일 | 내용 |
|---|---|
| `source/terms_auto_silson_excerpt.pdf` | 원문. 「보험업감독업무시행세칙」 [별표15] 표준약관(국가법령정보센터) 492쪽 중 자동차보험(개인용, 원본 78~143쪽)과 실손의료보험 기본형·특별약관1·2(원본 204~313쪽)만 발췌한 176쪽 |
| `chunk_terms.py` | 원문 PDF를 조항(제○조, 별표, 붙임) 단위로 자르고 읽기 좋게 정리하는 스크립트 (아래 '원문 정리') |
| `terms_chunks.jsonl` | 자른 결과 195조각 (한 줄 = 한 조각) |
| `../terms-rag.mjs` | 조각에서 관련 조항을 고르는 모듈 (`person-llm.mjs`가 사용) |

기준 버전: 자동차보험 2026.8.28. 개정, 실손의료보험 2026.5.6. 개정 반영본.

## 원문 정리

PDF에서 뽑은 글자를 그대로 쓰면 쪽 너비에서 끊긴 줄바꿈("보상하지 않\n습니다")과 표 칸 글자가 본문 사이에 섞여 화면에서 깨져 보입니다. `chunk_terms.py`가 다음처럼 정리합니다.

- **줄 잇기**: 항(①), 호(1.), 목(가.), 문장 끝에서만 줄을 바꾸고 나머지는 잇습니다. 띄어쓰기는 자동차 약관은 원문 줄 끝 공백으로, 실손 약관(원문에 공백 문자 없음)은 앞뒤 조각이 본문에 단어로 나오는지로 정합니다.
- **실손 조항 표 왼쪽 칸**: 보장종목 이름("(1) 상해급여")을 그 칸 첫머리에 `[보장종목: (1) 상해급여]` 줄로 넣습니다.
- **붙임(용어 | 정의 표)**: PDF의 표 가로선으로 행을 나눠 `용어: 정의` 한 줄씩으로 만듭니다.
- **◦ 표(자동차 제27조·제31조 제출 서류)**: 표 세로선으로 칸을 나눠 `서류 (필요한 보장종목, ...)` 한 줄씩으로 만듭니다.
- 오른쪽 여백의 개정 표기 조각("<신설", "2026.5.6.>")은 뺍니다.

정리 전 6,902줄(3글자 이하 토막 775줄) → 정리 후 1,678줄(12줄). 한 줄 안의 띄어쓰기는 원문 글자 간격 복원 그대로라 일부 붙어 있는 곳이 남아 있습니다.

## 조각 형식

```json
{"id":"T0134","doc":"실손의료보험 표준약관(기본형)","section":"제9관 다수보험의 처리 등",
 "article":"제37조","title":"다수보험의 처리","kind":"article","page":245,
 "cite":"실손의료보험 표준약관(기본형) 제37조(다수보험의 처리), 별표15 245쪽","text":"제37조(다수보험의 처리) ① ..."}
```

- `page`: 원본 별표15 쪽 번호
- `kind`: article(조항), appendix(별표·붙임·부표), intro(약관 머리말)
- 1,500자가 넘는 조항은 여러 조각으로 나누고 `part_no`/`parts`로 표시합니다.

## 조항을 고르는 방법 (`terms-rag.mjs`)

1. **고정 매핑**: 코드 판정에 정해 둔 조항을 붙입니다. 같은 입력이면 같은 조항이 나옵니다.

   | 코드 판정 / 지표 | 조항 |
   |---|---|
   | 중복 확실, 중복 의심 | 실손 제4조(보상하지 않는 사항: 자동차보험에서 보상받는 치료관계비) |
   | 고지 확인 | 실손 붙임1(용어의 정의: 상해) |
   | 판정 불가 | 실손 제7조(보험금의 청구), 자동차 제27조(제출 서류) |
   | 증빙 요청서, 판단 불가 보완 | 실손 제7조, 자동차 제27조 |

   치료 기간 지표는 팀 기준(같은 사고 유형 집단 상위 5%)을 쓰므로 약관의 경상 4주 기준(자동차 별표1)을 자동으로 붙이지 않습니다. 담당자가 물으면 키워드 검색으로 찾습니다.

2. **키워드 검색**: 담당자 질문은 글자 2개 단위 BM25로 비슷한 조항을 찾습니다. 외부 모델이 필요 없고, 점수 하한(8) 미만이면 붙이지 않습니다.

한 요청에 조항은 최대 3개입니다. LLM에는 매핑 조항은 사람이 쓴 **한 줄 요약 + 적용 문장**, 검색 조항은 **600자 발췌**를 보냅니다.

## 이 건에 어떻게 적용되는지 (적용 문장)

매핑 조항마다 코드가 이 사람의 근거 데이터로 적용 문장(`apply`)을 씁니다. 숫자와 번호는 근거 데이터에서만 나오고, 확정이 아니라 담당자가 확인할 내용으로 씁니다.

| 조항 | 적용 문장 예 |
|---|---|
| 실손 제4조 (중복 확실) | 사고 A0001(2025-03-02) 관련 청구 M0001: 같은 영수증의 치료비가 두 보험에서 모두 지급되었습니다(자동차보험 120,000원, 실손 120,000원). 자동차보험에서 보상받은 치료비는 실손에서 보상하지 않으므로, 실손 지급분이 이 조항의 보상 제외에 해당하는지 확인합니다. |
| 실손 제4조 (중복 의심) | 같은 병원·같은 치료 기간에 두 보험에서 비슷한 금액이 지급되었습니다. 같은 치료비라면 보상 제외에 해당하므로 서로 다른 비용 항목인지 확인합니다. |
| 실손 붙임1 (고지 확인) | 사고로 생긴 손상 진료인데 실손에는 질병으로 청구되었습니다. 상해에 해당하면 상해로 다뤄야 하므로 사고 경위와 청구 구분을 확인합니다. |
| 실손 제7조, 자동차 제27조 (판정 불가) | 양쪽 영수증 번호가 비어 있어 같은 치료비인지 판정할 수 없습니다. 이 조항의 청구 서류(진료비 계산서·영수증 등)로 확인합니다. |
| 실손 제7조, 자동차 제27조 (요청서·보완, 판정 없음) | 요청할 서류는 이 조항이 정한 청구 서류 안에서 고릅니다. |
| 질문 검색 조항 | 담당자 질문으로 찾은 조항이며 코드 판정과 직접 연결된 조항은 아님을 표시합니다. |

같은 판정이 여러 건이면 3건까지 쓰고 나머지는 '외 n건'으로 줄입니다.
LLM은 '관련 약관: (조항) — (이 건에 어떻게 적용되는지)'를 apply 안에서만 씁니다.
화면의 '관련 약관'은 조항 이름 아래에 적용 문장을 보여 주고, '조항 원문 보기'를 누르면 조각 전문이 펼쳐집니다(LLM을 거치지 않은 원문).

## LLM 입력 줄이기

교차 연결 중 '정상 분리 청구'는 개수(`normal_link_count`)만 보냅니다. 기왕증 기록이 있거나 담당자 질문에 번호가 나온 연결은 상세를 보냅니다.
데모 설명과 검증은 줄이지 않은 전체 근거를 씁니다. 데모 500명 기준 근거 JSON 최대 5,884자 → 3,142자.

## 검증

LLM 응답의 `term_refs`(인용한 조항 ref)가 넣어 준 조항에 없으면 기존 수치 검증 실패와 같이 데모 설명으로 대체합니다.
LLM에 보낸 조항의 숫자(예: 제4조, 4주)는 지어낸 숫자로 보지 않도록 검증 범위에 넣었습니다. 브라우저 쪽 재검증(`person-app.js`)도 같은 방식입니다.

## 다시 만들기

```bash
pip install -r rag/requirements.txt
python rag/chunk_terms.py rag/source/terms_auto_silson_excerpt.pdf rag/terms_chunks.jsonl
```

조 번호 누락 여부를 출력합니다. 표(별표1 등)는 PDF 배치 때문에 일부 줄 순서가 섞일 수 있습니다.
